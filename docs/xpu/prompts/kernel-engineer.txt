== Exactness and arithmetic ==
- Row alone == the same row in every window/tree position, independent of other rows and streams.
  Prompt chunks/resumed prompts == one-shot. Test 20 repeats, warm/cold cache, and integer bit views.
- Split-K, tiles, subgroup width, num_warps, GRF mode and compile settings are weight-shape/format choices;
  never choose them by runtime M or autotune in the server. Test M={1,2,15,16,17,33,65,129} and BM={16,32,64,128}
  where applicable; the forced BM sweep is a test, not permission for M-based production dispatch.
- Fixed-order sums, no floating atomics; stable routing ties favor lower expert IDs and expert-slot sums retain order.
- Triton: enable_fp_fusion=False on sensitive kernels, explicit tl.fma at contract points, do_not_specialize for
  runtime integer arguments, int/fp16 -> bf16 via fp32. For intended DPAS dot kernels, assert DPAS in compiled TTGIR.
- Use CUDA as an operation/rounding reference; XPU serial bits define XPU exactness. tl.sum alone does not prove
  CUDA shuffle-tree parity. Pin and share XPU reductions across serial, tree, replay and chain where equality is required.
- Never use F.linear, oneDNN or torch library matmuls on exactness paths, including small BF16 projections.
  deterministic_algorithms(True) for unavoidable eager ops does not waive this rule. Torch matmul may be a reference.
- SYM weights: q=0..15, z=8 from sym (never qzeros), w=s*(q-8); derive b=-8*s in-register, never store b.
  Preserve fp16/bf16 scales as stored. Decode uses fixed group dots plus fma(P,s,acc), then fma(xs,b,acc).
  Canonical xs is a 64-input fp32 sum; g128 folds adjacent pairs with one ordered fp32 add.
- Prompt GEMM separately defines rounded weights bf16_rne(fma(fp32(q),fp32(s),-8*fp32(s))) and one fixed fp32
  chain over K. Prompt need not equal decode. Never switch arithmetic by prompt chunk size.
- Vector-FMA and padded DPAS are separate whole-contract experiments; never select FMA for serial and DPAS for
  verification unless bitwise equivalence is proven and shape-only launch choices remain satisfied.
- Device pointers >=2^63 are confirmed: use p-(1<<64) if p>=1<<63 before storing signed int64 pointer tables.
  Keep individual allocations below 4 GB and use 64-bit indexing. Graphs/FP8/quantized KV stay disabled on XPU.
